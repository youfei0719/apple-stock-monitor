# 补货监控商品目录标准

本工具的目录是一份**补货需求清单**。Apple 中国官网是型号、SKU、颜色、容量、配置与价格的权威来源，但官网的全量商品列表不等于本站的推荐列表。

## 先决定哪些商品值得监控

- 优先选择新近发售、用户需要等补货或抢购的重点机型。
- 必须有具体门店缺货证据，才能作为默认补货目标。一般现货、没有补货需求依据的常规产品不自动加入。
- 先人工确定重点产品系列，再在该系列里筛选有缺货信号的具体 SKU；不逐个品类自动铺货，不为了“覆盖品类”加入 AirPods、HomePod 等现货。
- 某家门店一次有货不能证明“全国长期充足”，某家缺货也不能证明“全国都缺货”。证据必须保留门店与核验时间。
- 补货后仍保留已经创建的监控任务。是否移出推荐清单应按持续供应恢复情况人工复核，不能随着一次查询结果反复移除、重加。

## 再补全入选商品的配置

- 从官网购买页取真实商品编号、价格、中文配置和官方链接，不推测 SKU，不制造不存在的容量 × 颜色 × 网络组合。
- 补货商品必须具有独立 `part_number` 并通过门店库存查询验证。`unavailable` 是可监控的缺货状态；接口失败、缺字段、`ineligible` 都不是缺货证据。
- SKU 与硬件型号 (`Axxxx`) 分开，官网未提供硬件型号时留空。
- 普通现货、任意 CTO、刻字及服务不进入默认清单。未开放购买的新品仅在用户明确需要提前预约、已有官方配置与预购时间时收录，并标记 `prelaunch_watch`。Watch 表壳库存不代表表壳加表带的整套库存。
- 推荐清单通过 `admission` 保存加入原因、缺货门店和时间；瞬时查询状态不充当页面实时库存。

## 本轮收录与更新

2026-10-12：只选择 iPhone 18 Pro 与 iPhone 18 Pro Max 中已出现缺货信号的配置。首次证据来自 Apple 南京东路 (R359)，不是全国缺货报告。其他品类暂无加入依据，前端隐藏其入口。iPhone Duo 增加 8 个官方配置作为提前预约目标：2 色 × 4 容量。预计 2026-10-16 20:00（北京时间）接受预购，2026-10-23 发售，须获批准，具体以 Apple 实际开放购买为准。这 8 个条目不宣称完成库存验证。

快照：`backend/app/data/apple_catalog.json`。来源带 URL、SHA256 和官网配置总数；推荐条目带库存核验与补货需求证据。旧数据库种子不再遮蔽新清单，历史任务和自定义配置仍保留。

```sh
backend/.venv/bin/python scripts/sync_apple_catalog.py --cache /tmp/apple-restock-catalog
python3 scripts/validate_catalog.py
```

脚本默认仅研究 `SOURCES` 中人工选定的重点系列，且只接纳样本门店实际缺货的 SKU。使用人需复核目标门店与持续供应情况，不能把这个单店检查当成全国热度或长期供货判断。限流采用等待与有限重试；失败不覆盖原快照。更新后重启 API 载入，无数据库结构迁移。

`SEED_STORES` 是降级目录；全国门店独立经后台刷新。本轮不改门店范围。

## 提前预约接口

目录 `launch` 保存 `preorder_at`、`release_date`、官方说明与来源链接。现有单建/批量任务接口支持预先选择 SKU 与门店，服务端要求登录，默认无到期时间；匿名 24 小时体验不能创建预约监控。开售前展示 `scheduled`，不查询库存、不扣提醒额度，也不计算为长期缺货。到官方预购时间自动激活正常检查；只有 Apple 实际返回所选门店可自提才提醒，接口失败或不支持自提不算有货。暂停、到期、渠道与额度限制照常生效。官方延期开售时维护 `PRELAUNCH` 和快照并重启 API 与独立引擎，用户无需重新建任务。
