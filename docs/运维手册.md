# 运维手册（StockMon）

## 服务一览

| 服务 | systemd | 端口/路径 |
|---|---|---|
| API | `stockmon-api` | 127.0.0.1:8101 |
| 监控引擎 | `stockmon-engine` | 独立进程 |
| 前台 | nginx static | `/opt/stockmon/frontend/dist` |
| 后台 | nginx static | `/opt/stockmon/admin/dist` → `/admin/` |
| 备份 | cron 每天 3:10 | `deploy/backup.sh` |

常用命令：`systemctl status|restart stockmon-api stockmon-engine`；日志 `journalctl -u stockmon-api -f` + `/opt/stockmon/logs/`。

## 开关与调度

### ENGINE_ENABLED（引擎开关）
- `.env` 里 `ENGINE_ENABLED` 默认 `false`：API 进程（`stockmon-api.service`）不启动引擎。
- 独立引擎进程由 `deploy/stockmon-engine.service` 启动，unit 里显式 `Environment ENGINE_ENABLED=true`，是**全站唯一**的引擎运行者。
- 严禁在 API 进程的环境里把开关打开（双引擎重复轮询/重复通知）；手动在 shell 跑 `python -m app.services.engine` 会走 fail-fast 检查，开关未开直接拒绝启动。
- 排查"引擎没在跑"：`curl /api/admin/system` 看 `engine.running`（读引擎写进 DB 的心跳，60s 内有心跳 = running），或 `journalctl -u stockmon-engine`。

### membership_sweep（会员生命周期调度）
- 不是 cron：跑在引擎进程内，每 60 tick（默认 tick=5s，约 5 分钟）执行一次 `run_lifecycle_sweep`（`backend/app/services/lifecycle.py`）。
- 做三件事：① standard/pro 到期自动降级（到期后切换 `pending_tier`，降级后超限任务自动暂停）；② 到期前 3 天 / 1 天续费提醒（邮件）；③ 僵尸任务 nudge（断裂链路，见代码注释）。
- 排查：日志搜 `lifecycle_sweep_failed`；单子 sweep 异常只记日志，不中断引擎主轮询。

### SQLite WAL（写并发）
- 应用内连接默认 `PRAGMA journal_mode=WAL` + `busy_timeout=5000`（`backend/app/core/db.py`），读/写可并发，写锁等待 5s 再报错。
- 备份脚本（`deploy/backup.sh`）用 `PRAGMA busy_timeout=15000`（15s），与引擎写锁撞车时多等一会儿；备份失败（产物为空/完整性校验不过）会写日志并**非零退出**，cron 会感知到。
- 注意：WAL 模式下库文件旁边有 `app.db-wal`/`app.db-shm`，恢复备份时三个文件视为一体；不要只拷 `app.db`。

## 订单处理（后台 /api/admin/payments）

订单状态：`paid`（已支付）· `amount_mismatch`（金额与档位不符，待人工）· `refunded`（已标记退款）· `resolved`（人工关闭/处理完毕）· `cancelled`。

- **认领** `POST /api/admin/payments/{id}/claim {"user_id":N}`：未认领订单（用户赞助后没填邮箱/账号对不上）绑定用户 + 按订单档位开通 30 天（到期/配额锚点同步）+ 回填 `Payment.user_id`；若原状态为 `amount_mismatch`，成功后自动置 `resolved` 并待处理计数 -1。全程记审计。
- **关闭（不处理）** `POST /api/admin/payments/{id}/close`：人工定夺为"不予开通"时用。`status` 置 `resolved`（移出待处理队列），不绑定用户、不开通档位；`amount_mismatch` 时待处理计数 -1。记审计。
- **标记退款** `POST /api/admin/payments/{id}/refund`：`status` 置 `refunded`（收入统计只计 paid，自动排除）+ 该用户降回 `free` 并清空 `tier_expires_at`/`pending_tier`。**实际退款钱款在爱发电后台操作**，本接口只标记账务状态 + 联动降级。记审计。
- 待处理徽标（`pending_payments`）= `unclaimed` + `amount_mismatch`；上述三操作都会同步递减计数，徽标不会长期误报。

## 常见故障

### 1. Apple 接口被限流（541/403）
- 现象：任务状态大面积 `unknown`/`cooling`，日志 `apple_541_cooldown`。
- 处理：属预期行为，引擎会自动指数退避。检查：`curl /api/admin/system` 看限流状态；不要手动调高频率。
- 若持续 30 分钟以上：检查出口 IP 是否被 Apple 封禁，考虑启用 `PROXY_POOL` 轮换。

### 2. 邮件发不出
- 检查 `.env` 的 SMTP_HOST/USER/PASSWORD；用 `POST /api/notify/test` 自测。
- QQ/163 邮箱易进垃圾箱：优先用阿里云 DirectMail / SendCloud。

### 3. 爱发电支付回调失败
- 爱发电后台确认 webhook URL 为 `https://stock.glint.red/api/pay/afdian-webhook`。
- 检查 `AFDIAN_TOKEN` 是否正确；日志搜 `afdian_webhook`；失败订单在 `/api/admin/payments` 人工补单（改级）。

### 4. 后台无法登录
- 确认 `ADMIN_EMAIL/ADMIN_PASSWORD` 在 `.env`；首次启动自动建号，之后清空密码字段。
- TOTP 丢了：进库 `UPDATE users SET totp_secret=NULL WHERE email='x'` 后重新绑定。

### 5. 磁盘/备份
- 备份在 `/opt/stockmon/backups`，保留 14 天。恢复：`sqlite3 /opt/stockmon/backend/data/app.db ".restore '/opt/stockmon/backups/app-YYYY-MM-DD.db'"` 后重启服务。
